# Current experiment: 2^23 gates on r5.24xlarge

This plan replaces the 2^24/X8i launch plan. Start from a fresh Ubuntu 26.04 LTS
x86-64 instance and rebuild the tested source on the R5 CPU. A custom AMI is
optional. The completed Linux rehearsal remains valid evidence for the workflow;
the new host gets a short smoke test rather than another complete rehearsal.

## Experiment specification

| Setting | Value |
|---|---|
| Instance | r5.24xlarge: 96 vCPUs, 768 GiB nominal RAM |
| Total gates | 2^23 = 8,388,608 |
| Field and permutation | BN254; identity |
| Public inputs | 256, all equal to 9 |
| WHIR interleaving | 16 in the first and subsequent rounds |
| Update sizes | 1, 2, 4, 8, 16, 32, 64, 128 gates |
| Sequence length | 40 consecutive random updates per size |
| Starting states | One shared full initial computation; each size starts independently from that state |
| Baseline | 40 shared HyperPlonk proofs, paired with the one-gate revisions |
| Seed | 20260909 |
| Prover/verifier time | Mean and maximum across forty proofs; initial computation measured once |
| Proof size | Mean and maximum of the entire retained proof, both field/hash payload and serialized CBOR |
| Cleanup | Absorbed hierarchy levels are removed from the retained proof |
| Rayon | Calibrate 48 versus 96 workers, then use one count for every measured phase |
| Storage | 50 GiB gp3 root; 100 GiB gp3 results volume with Delete on termination disabled |

Gate positions are sampled without replacement within each revision; positions can
repeat across revisions. The workload and proof accounting match the completed
Linux rehearsal. Eight update sizes give **361 verified samples**: one initial,
forty baseline and 320 updates. **Ten CBOR checkpoints** are retained: initial,
final baseline and final update proof for each size. No warmup observations are
discarded. Timers exclude serialization and disk writes.

The exact seeded preflight projects **468 GiB**, dominated by initialization.
This is an allocation estimate, not measured peak RSS. It is below 70% of 768 GiB
(537.6 GiB); the actual run checks detected host/cgroup RAM. Keep that guard enabled.
The previous 2^15 rehearsal measured 28.674 GiB for a different workload and does
not establish the peak for this run. Its runtime on X8i also does not establish
R5 runtime; use the new host's calibration before scheduling the full experiment.

[AWS R5 specifications](https://aws.amazon.com/ec2/instance-types/r5/).
The launching account needs 96 available vCPUs in the appropriate **Standard**
On-Demand or Spot quota, which includes R instances. Its quota is independent of
the source account's X quota. [AWS quota groups](https://docs.aws.amazon.com/ec2/latest/instancetypes/ec2-instance-quotas.html).

## 1. Launch and transfer the source

Have the account owner launch the instance with your public key, SSH access from
your IP and the storage above. Obtain its public address and confirm the Ubuntu
SSH username. The key file below must correspond to the public key they installed.

From the Mac:

```sh
BENCH_HOST=YOUR_PUBLIC_IP
BENCH_KEY="$HOME/Downloads/awsKey.pem"
cd /Users/anubhavbaweja/Desktop/Research/research-git/dynamic-snarks-system
scp -i "$BENCH_KEY" \
  benchmark-results/ec2-experiment-r5-n23-u128-i16-r40-20260916.tar.gz \
  benchmark-results/ec2-experiment-r5-n23-u128-i16-r40-20260916.tar.gz.sha256 \
  "ubuntu@$BENCH_HOST:"
ssh -i "$BENCH_KEY" "ubuntu@$BENCH_HOST"
```

This package includes uncommitted optimizations from the tested working tree;
cloning the GitHub repository alone may not reproduce it. It contains source,
scripts and documentation, with no SSH private key or compiled X8i binary.

## 2. Install, compile, preflight and smoke-test the new host

On the fresh instance:

```sh
cd "$HOME"
sha256sum -c ec2-experiment-r5-n23-u128-i16-r40-20260916.tar.gz.sha256
tar --keep-old-files -xzf ec2-experiment-r5-n23-u128-i16-r40-20260916.tar.gz
cd "$HOME/dynamic-snarks-system"
nohup bash scripts/prepare_r5_experiment.sh "$HOME/bench-results/prep-r5-n23-20260916" \
  > "$HOME/snark-r5-prep-20260916.log" 2>&1 < /dev/null &
```

Preparation runs detached from SSH. It installs Rust 1.92.0 and dependencies,
checks the result utilities, builds with `-C target-cpu=native`, refreshes the
2^23 preflight, and proves a small 512-gate case with forty one-gate updates. The
smoke test expects 81 verified samples and three checked CBOR files. The helper
does not start the full experiment. Do not use the older
`prepare_ec2_experiment.sh` here, since it repeats the long 2^15 rehearsal.

```sh
cat "$HOME/bench-results/prep-r5-n23-20260916/prep-status.txt"
tail -n 30 "$HOME/snark-r5-prep-20260916.log"
```

Wait for `complete: ready for worker calibration and the full run` before continuing.

## 3. Mount the results volume and calibrate workers

Mount the separate results volume at `/mnt/bench-results` and make it writable by
`ubuntu`. Inspect the attached disks and existing filesystems before selecting or
formatting a device; the device name is host-specific. The following commands
require an actual mounted volume at that location.

Start a persistent shell, then run the remaining commands inside it:

```sh
tmux new -s snark-bench
```

```sh
set -e
cd "$HOME/dynamic-snarks-system"
source "$HOME/.cargo/env"
export RUSTFLAGS='-C target-cpu=native'
unset DYNAMIC_SNARK_PROFILE DYNAMIC_SNARK_PROFILE_DETAIL
export BENCH_RESULTS=/mnt/bench-results
if ! mountpoint -q "$BENCH_RESULTS" || ! test -w "$BENCH_RESULTS"; then
  echo 'Mount the retained results volume and make it writable by ubuntu first.' >&2
  exit 1
fi
findmnt "$BENCH_RESULTS"

for BENCH_THREADS in 48 96; do
  python3 scripts/run_experiment.py --trace-log 20 --threads "$BENCH_THREADS" \
    --initial-interleaving 16 --update-logs 6 --sequence-len 3 \
    --seed 20260909 --baseline-mode shared --offline --numa-interleave \
    --output "$BENCH_RESULTS/calibration-n20-t$BENCH_THREADS"
done
```

Compare `resources.json` and `comparison.csv`, including initial, baseline and
update proving times. These calibration runs are separate from the experiment.
Select a worker count for the full run. The example below uses 48; use 96 if the
calibration supports that choice. Each output directory must be new.

## 4. Run and validate the full experiment

```sh
BENCH_THREADS=48
python3 scripts/run_experiment.py --trace-log 23 --threads "$BENCH_THREADS" \
  --initial-interleaving 16 --update-logs 0,1,2,3,4,5,6,7 \
  --sequence-len 40 --seed 20260909 --baseline-mode shared \
  --offline --numa-interleave --output "$BENCH_RESULTS/full-n23-u128"

jq -e '.state == "complete" and .exit_code == 0' "$BENCH_RESULTS/full-n23-u128/status.json"
jq -e '.complete and .verified_samples == 361 and .proof_size_samples == 361 and .proof_checkpoints == 10' \
  "$BENCH_RESULTS/full-n23-u128/validation.json"
cd "$BENCH_RESULTS/full-n23-u128"
sha256sum -c SHA256SUMS
```

Detach with Ctrl-b then d; reconnect with `tmux attach -t snark-bench`.
Raw samples are persisted after each verified proof. A Spot interruption requires
reinitializing the prover; CBOR files are verification checkpoints, not resumable
prover state. Retain the results volume to preserve completed measurements.

## 5. Copy results to the Mac

From a Mac terminal, using the same BENCH_HOST and BENCH_KEY values:

```sh
mkdir -p "$HOME/Downloads/snark-r5-n23-results"
scp -i "$BENCH_KEY" \
  "ubuntu@$BENCH_HOST:/mnt/bench-results/full-n23-u128.tar.gz" \
  "$HOME/Downloads/snark-r5-n23-results/"
cd "$HOME/Downloads/snark-r5-n23-results"
tar -xzf full-n23-u128.tar.gz
cd full-n23-u128
shasum -a 256 -c SHA256SUMS
```

`comparison.csv` contains prover and verifier means/maxima.
`proof-size-comparison.csv` contains payload and CBOR means/maxima and final sizes.
`samples.csv` retains every observation. The archive also includes the source,
configuration, build metadata, workload, proof files, status and peak RSS/wall time.
Check the copied results before terminating the instance.
